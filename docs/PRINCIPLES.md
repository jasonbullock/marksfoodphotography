# Marks Photo Principles

These principles support `docs/PRODUCT_VISION.md`. The product is an operational readiness system for merchandise moving through Walnut Studio, not a project management platform, PIM, or system of record.

Marks Photo owns operational information required to execute production and report production. It does not own project planning, client communication, budgeting, approvals, or project task management.

## 1. Work appears automatically.

People should not create administrative records.

---

## 2. Physical merchandise drives production.

Not spreadsheets.

Not imports.

Not emails.

Merchandise.

---

## 3. Users make decisions.

Software manages state.

---

## 4. The interface should answer:

"What do we need to do with this merchandise right now?"

Never:

"What records do I need to maintain?"

---

## 4a. Navigation follows operational questions.

Primary navigation should expose the operational command center:

- Dashboard
- Receiving
- Merchandise
- Planning
- Production

Supporting records such as Products, Jobs, Imports, Issues, Clients, and Airtable diagnostics should not become the normal primary navigation model.

---

## 5. Prefer queues over status fields.

Queues represent work.

Statuses represent data.

Workflow gates represent ownership changes or business decisions.

Do not create Marks Photo workflow gates for every production system event. Queued, assigned, retouch, QC, export, upload, and similar production details belong to Creative Force metadata.

Workflow answers "who owns the next decision?"

Status answers "what is currently true?"

---

## 6. Every click should eliminate work.

Not create work.

---

## 7. Never ask the user for information we already know.

Auto-match.
Auto-group.
Auto-suggest.
Auto-fill.

---

## 8. Progressive disclosure.

Only ask the next necessary question.

---

## 9. The software should think first.

Humans should confirm.

---

## 10. Simplicity wins over completeness.

---

## 11. Client rules determine readiness.

The application should evaluate whether Walnut can photograph merchandise based on each client's requirements, regardless of where the information originated.

---

## 12. Enter only missing information.

If Product or Job information already exists, reuse it. If it does not, collect the smallest amount of information needed to make the Merchandise operationally ready.

---

## 13. Capture readiness, execution, and reporting information.

Capture only the operational information Walnut Studio needs to:

- determine readiness
- execute production
- report completed work

Nothing more.

Nothing less.

Reporting references such as Job Number, Client Project Number, External Reference, Service Type, Activation, and Deliverable Type are operational references, not project-management fields.
